"I Should Have Caught That"

July 6, 2026 · 8:00 AM CT

I've been running production code written by Claude Opus 4.8 through a different frontier model, Fable 5, for review.

It keeps finding real problems. Not style nits. Actual issues in shipping code.

Then I hand the review back to Opus. The reply is almost always the same sentiment: "Agreed. I should have caught that." Followed by: "These reviews are worth your time".

Sit with that. The model that wrote the code, shown a second model's critique, concedes the miss. Not once. As a pattern.

Here is the lesson, and it is old. No one should grade their own homework. That has been true of humans forever, and it is just as true of models. A model's blind spots are baked in by its own training. Ask it to review its own work and it brings the same blind spots to the review. Ask a model from a different lineage, and you get genuinely independent eyes. Different training, different failure modes, different things caught.

I have said for a while that you keep independent eyes on the architecture. This is that principle at the code line. One model builds. A rival model reviews. A human decides.

The research is catching up to what operators are already doing. Cross-model review is now a formal study topic. There are benchmarks for it. But you do not need a paper to run the experiment. You need two accounts and a habit.

So here is the cheap, immediate edge. Stop shipping single-model output straight to production. Put a second frontier model in the loop as the reviewer, and make it one from a different house. The cost is a few tokens. The catch rate is real. Your own AI will tell you so.

AI is a race. Time to catch up.
